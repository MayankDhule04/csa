# Terraform — Cloud Security PBL Unit 1

Infrastructure-as-Code for the 3-tier web application. This README covers how to
run the Terraform itself. For the full project write-up, see the
[root README](../README.md) and the [`docs/`](../docs) folder.

## File layout

| File | Purpose |
|------|---------|
| `versions.tf` | Terraform & provider version constraints |
| `provider.tf` | AWS provider + `default_tags` (no credentials in code) |
| `variables.tf` | All configurable inputs with sensible defaults |
| `locals.tf` | Derived names, AZ list, subnet CIDRs |
| `data.tf` | AZ lookup, caller identity, latest AL2023 AMI |
| `vpc.tf` | VPC + Internet Gateway |
| `subnets.tf` | Public / app / db subnets + DB subnet group |
| `routes.tf` | Route tables, NAT gateway, associations |
| `security_groups.tf` | ALB / app / db security groups (least privilege) |
| `load_balancer.tf` | ALB, target group, HTTP listener |
| `application.tf` | IAM role, launch template, Auto Scaling Group |
| `database.tf` | Random password → SSM SecureString, RDS MySQL |
| `outputs.tf` | VPC/subnet IDs, ALB URL, DB endpoint, etc. |
| `templates/user_data.sh.tpl` | App bootstrap (httpd + DB connectivity test) |
| `terraform.tfvars.example` | Copy to `terraform.tfvars` and edit |

## Prerequisites

- Terraform >= 1.5
- AWS CLI authenticated for an account/region where you can create VPC, EC2,
  ELB, RDS, IAM, SSM, and KMS resources — preferably via IAM Identity Center
  (`aws configure sso`); see "Configure credentials" below.
- Permissions to create the above resources.

## Configure credentials (never commit these)

Preferred: **AWS IAM Identity Center (SSO)** — short-lived, auto-rotated creds.

```powershell
aws configure sso                     # one-time; browser sign-in, pick account/role
aws sso login --profile cloudsec-pbl  # start a session (repeat when it expires)
$env:AWS_PROFILE = "cloudsec-pbl"     # Terraform reads this profile automatically
aws sts get-caller-identity           # verify identity/account/region
```

Alternative (only if SSO is unavailable): static IAM access keys.

```powershell
aws configure                         # stores keys in ~/.aws/credentials (never commit)
aws sts get-caller-identity           # verify
```

## Deploy

```powershell
cd terraform
Copy-Item terraform.tfvars.example terraform.tfvars   # optional: edit values
terraform init
terraform fmt -check
terraform validate
terraform plan
terraform apply           # type "yes" to confirm
```

After apply, open the demo:

```powershell
terraform output alb_url
```

> The app tier runs `dnf update` + installs `httpd` on boot and the ALB waits
> for health checks, so the page may take 2–4 minutes to become reachable.

## Validate only (no AWS account needed)

```powershell
terraform init -backend=false
terraform fmt -check
terraform validate
```

## Destroy (stop all charges)

```powershell
terraform destroy         # type "yes" to confirm
```

## Notes

- The DB password is generated by Terraform and stored in SSM Parameter Store
  as a SecureString — it is never printed or committed.
- `terraform.tfvars`, `*.tfstate`, and `.terraform/` are git-ignored.
- Billable resources: NAT Gateway, ALB, EC2 (x2), RDS. Run `destroy` when done.
